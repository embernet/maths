The R you learned from a textbook a decade ago looked different from the R people actually write today. **Hadley Wickham**, working largely at RStudio (now Posit), led a redesign of the day-to-day data-analysis interface — the result is the **tidyverse**: a collection of opinionated, consistent packages built around the idea of *tidy data*.

The flagship pieces are **dplyr** (data manipulation), **tidyr** (reshaping), **ggplot2** (graphics), **purrr** (functional iteration), **readr** (file I/O), **stringr** (strings), and **lubridate** (dates).

## Tidy data

A "tidy" data frame has three properties:

1. Each variable is a column.
2. Each observation is a row.
3. Each value is a single cell.

This is the same shape that relational databases assume. Statistical functions in R generally expect it, and getting your data into this shape is the first step of any analysis. The verbs of the tidyverse are designed for tidy data and produce tidy data.

## dplyr verbs

Five verbs do most of the work.

```r
library(dplyr)
library(ggplot2)

data(mtcars)
mtcars <- as_tibble(mtcars, rownames = "model")

# 1. filter — pick rows by condition
mtcars |> filter(mpg > 25)

# 2. select — pick columns by name
mtcars |> select(model, mpg, cyl)

# 3. mutate — add or modify columns
mtcars |> mutate(kpl = mpg * 0.4251)

# 4. arrange — reorder rows
mtcars |> arrange(desc(mpg))

# 5. summarise — collapse to one row (often per group)
mtcars |>
  group_by(cyl) |>
  summarise(
    n        = n(),
    avg_mpg  = mean(mpg),
    avg_hp   = mean(hp),
    avg_wt   = mean(wt),
  )
```

The native pipe `|>` chains verbs left-to-right. A multi-step analysis reads as a list of instructions, each on its own line. This is the dplyr style — declarative, almost SQL-like, but inside R with full access to vectors and functions.

### Joins

```r
# inner_join, left_join, right_join, full_join — all SQL-style
orders <- tibble(order_id = 1:3, customer_id = c(1, 1, 2), amount = c(50, 80, 30))
customers <- tibble(customer_id = c(1, 2, 3), name = c("Alice", "Bob", "Carol"))

orders |> left_join(customers, by = "customer_id")
```

### Window functions

```r
mtcars |>
  group_by(cyl) |>
  mutate(
    rank_mpg = rank(-mpg),               # rank within cylinder group
    mpg_z    = (mpg - mean(mpg)) / sd(mpg)
  )
```

`mutate` after `group_by` keeps the row count but computes within groups. `summarise` collapses each group.

## tidyr: pivoting

Real data often arrives in "wide" form when you want it "long", or vice versa.

```r
library(tidyr)

# Wide → long
sales_wide <- tibble(
  store = c("A", "B"),
  jan   = c(100, 150),
  feb   = c(120, 170),
  mar   = c(135, 180),
)
sales_long <- sales_wide |>
  pivot_longer(cols = jan:mar, names_to = "month", values_to = "sales")
print(sales_long)
# store month sales
# A     jan     100
# A     feb     120
# A     mar     135
# B     jan     150
# ...

# Long → wide
sales_long |> pivot_wider(names_from = month, values_from = sales)
```

Most statistical and plotting functions in R want long form. tidyr makes the conversion routine.

## ggplot2: the grammar of graphics

ggplot2 implements Leland Wilkinson's **grammar of graphics**: a plot is a *layered composition* of data, geometric objects (`geom_*`), aesthetic mappings (which variable controls which visual property), statistical transformations, scales, coordinates, and facets.

Start with data and an aesthetic mapping, then add layers with `+`.

```r
ggplot(mtcars, aes(x = wt, y = mpg, colour = factor(cyl))) +
  geom_point(size = 3, alpha = 0.8) +
  geom_smooth(method = "lm", se = FALSE) +
  scale_colour_brewer(palette = "Set1", name = "Cylinders") +
  labs(
    title = "Fuel efficiency vs car weight, by cylinder count",
    x = "Weight (1000 lbs)",
    y = "Miles per gallon"
  ) +
  theme_minimal()
```

What's happening:

- `ggplot(data, aes(...))` sets the data and the aesthetic mappings (the *variables* that drive position, colour, shape, etc.).
- `geom_point(...)` adds points.
- `geom_smooth(method = "lm")` adds linear-regression fits (with confidence bands by default; `se = FALSE` removes them).
- `scale_colour_brewer` chooses a palette.
- `labs` sets titles.
- `theme_minimal` switches off the grey background.

Each layer is independent and composable. The plot is built from the data outwards.

### Common geoms

| Geom | What it draws |
|------|---------------|
| `geom_point()` | Scatter plot |
| `geom_line()` | Connected line |
| `geom_bar()` / `geom_col()` | Bars (counts vs values) |
| `geom_histogram()` | Histogram |
| `geom_density()` | Kernel density estimate |
| `geom_boxplot()` | Box-and-whisker plot |
| `geom_violin()` | Violin plot |
| `geom_smooth()` | Smoother (linear, loess, GAM) |
| `geom_text()` / `geom_label()` | Text annotations |
| `geom_tile()` | Heatmap squares |
| `geom_hex()` | Hex-binned scatter |

### Facets

Faceting splits a single plot into a grid of small multiples — one per group. This is the killer feature for exploratory data analysis.

```r
ggplot(mtcars, aes(wt, mpg)) +
  geom_point() +
  geom_smooth(method = "lm") +
  facet_wrap(~ cyl, ncol = 3) +
  labs(title = "Fuel efficiency vs weight, faceted by cylinder count")
```

A single line — `facet_wrap` — and the plot is now three plots, identically scaled, side by side. Adding a categorical dimension to an analysis becomes trivial.

### Themes

ggplot2 ships with several themes: `theme_grey` (the default), `theme_bw`, `theme_minimal`, `theme_classic`, `theme_void`. The `ggthemes` package adds journal-specific themes (Economist, FiveThirtyEight, Tufte, etc.). For papers, `theme_classic()` is a common choice.

```r
theme_set(theme_minimal())   # apply to all subsequent plots in this session
```

## A worked end-to-end example

```r
library(tidyverse)

# Read a CSV — readr handles types intelligently
sales <- read_csv("monthly_sales.csv")

# Clean and reshape
clean <- sales |>
  filter(!is.na(revenue), region %in% c("Europe", "Asia", "Americas")) |>
  mutate(
    month = lubridate::ymd(month),
    year  = lubridate::year(month),
  )

# Aggregate
yearly <- clean |>
  group_by(region, year) |>
  summarise(total = sum(revenue), .groups = "drop")

# Plot
ggplot(yearly, aes(year, total, colour = region)) +
  geom_line(linewidth = 1.1) +
  geom_point(size = 2.5) +
  scale_y_continuous(labels = scales::label_dollar(scale = 1e-6, suffix = "M")) +
  labs(
    title = "Annual revenue by region",
    x = NULL,
    y = "Revenue",
    colour = NULL,
  ) +
  theme_minimal(base_size = 13)
```

Read, clean, aggregate, plot. Twenty lines from a raw CSV to a publication-quality figure.

## The tidyverse style in summary

A few principles you'll see throughout:

1. **Pipe everything.** Multi-step transformations flow through `|>` with one verb per line.
2. **Verbs, not adjectives.** `filter`, `mutate`, `select`, `arrange`, `summarise` — every operation has an obvious imperative name.
3. **Tidy in, tidy out.** Each verb takes a tidy data frame and returns a tidy data frame, so they compose freely.
4. **Aesthetic separation.** In ggplot2, `aes()` is for variable-driven properties; constants (`size = 3`, `colour = "red"`) go *outside* `aes()`.
5. **Readability over brevity.** A multi-line dplyr chain that reads in English is preferred over a one-liner that doesn't.

The tidyverse is opinionated. Some R users prefer base R or **data.table** (which is faster for large data and reads more like SQL). All three styles coexist; pick the one that fits your code's mood.
